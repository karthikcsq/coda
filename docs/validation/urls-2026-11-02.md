# Spoken URL cleanup, November 2, 2026

Smart cleanup now formats explicit URL spelling before the optional cleanup worker.
The existing protected-text guard previously left URL-like text untouched, including
spoken separators. This native, deterministic path also works without the worker or
model assets; it does not fetch, open or validate the destination website.

Examples:

- `style.fyi slash style dash md` → `style.fyi/style-md`
- `example dot com slash docs slash README dot md` → `example.com/docs/README.md`
- `https colon slash slash example dot com slash Docs` → `https://example.com/Docs`
- `example.com slash search question mark q equals voice ampersand mode equals smart`
  → `example.com/search?q=voice&mode=smart`

Only bounded URL spans change. Host names use lowercase; path/query capitalization
is preserved. Explicit slash, dash/hyphen, dot, underscore, query and fragment cues
are supported. Ordinary prose after a path is not joined into it. Spoken query markers
need a key/value cue. A standalone formatted URL loses an ASR sentence-ending period;
sentence punctuation in surrounding prose stays outside the URL.

Quoted/code/verbatim text, existing correctly formatted URLs, ordinary uses of slash
and dash, sentence boundaries and ambiguous mentions such as “use dot net” stay intact.
Without a scheme, recognition is limited to common domain suffixes. None and Light
retain their existing behaviour; the original transcript remains in History. The
dictionary correction classifier bypasses this formatting path.
