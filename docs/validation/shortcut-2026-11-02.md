# Control–Option dictation recovery, November 2, 2026

The user reported that holding Control–Option left the popup ready without recording;
they confirmed its microphone button did start recording. Running Coda Settings showed
Control–Option/Hold, microphone access enabled, Accessibility enabled and Voz ready.

The modifier listener previously depended on AppKit delivering the initial flagsChanged
event. Its watchdog could only release or cancel, so it could not recover a missed
press. The watchdog now feeds held-key state through the same debounced chord state
machine for both presses and releases. It runs in common run-loop modes. A Boolean
check for other held keys prevents another Control–Option shortcut from starting
dictation; the delayed activation rechecks keys and existing access. No key contents
are retained, and events are not intercepted. A fresh release is required after restart.

Polling stops on lock, sleep, screen sleep or inactive user sessions. Independent pause
reasons must all clear before the listener resumes. The HUD now distinguishes microphone
startup, transcription, cancellation and failure, and shows the actual startup/error
message instead of hiding it behind a ready label and shortcut hint.
