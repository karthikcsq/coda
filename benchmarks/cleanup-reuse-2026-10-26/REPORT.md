# Smart cleanup 0.4.10 — October 26, 2026

## Behavior and design

The user's latest preference supersedes earlier filler preservation: remove clear `um`, `uh`, `erm` and unambiguous discourse `like`; retain meaningful `like`, hedges, emphasis, negation and substantive words. Source edits normalize known spoken slash labels and `domain-specific`, apply bounded explicit corrections, format clear named/counted/colon lists and consecutive action steps, and split longer prose at existing sentence boundaries. Ambiguous category boundaries remain prose. Short prose is not forced into paragraphs. Final conjunctions are retained, including in bullets. No invented headings or paraphrase.

For text without sentence punctuation, a separate Apache-2.0 Horizon-Labs punctuation classifier predicts marks rather than words. Coda's clean-room renderer inserts finite marks at original source offsets. Existing punctuation, numbers and word characters are never reconstructed. Protected quotes, code, URLs, literal punctuation discussions, embedded instruction attacks, existing sentences and explicit formatting commands bypass this model. The optional classifier does not correct ASR vocabulary mistakes. None retains exact raw text; History retains originals; meeting transcripts do not enter this pipeline.

The source editor is ready before either model loads. Punctuation warms in a background thread during dictation. The existing Qwen3.5-2B model now loads lazily only for unsupported correction cases; common cleanup does not load it. While a backend is cold or unavailable, validated native cleanup remains available. Generative output retains the 650 ms generation budget and 900 ms native deadline. Missing assets, errors, cancellation, occupied workers, oversized input and invalid edits have guarded fallbacks. A filler-only utterance inserts nothing and saves its raw original.

- 60 core Swift tests and 27 native UI cases passed. One opt-in insertion fixture was skipped (28 UI cases including that skip). Native tests cover stale/cancelled results, fallback deadlines, filler-only raw-history recovery and meeting/menu routes.

One unpunctuated pair of sentences received a comma splice instead of the expected period. This miss is retained in `integrated-results.json`; the evaluator asserts lexical safety and reports structure utility separately. - Separate classifier trials: 30 direct outputs and 39 guarded robustness outputs preserved source words. The guarded run tagged 21 outputs and bypassed 18, preserving original characters/punctuation in all 39. Cold import/session/tokenizer readiness varied 562–975 ms. Peak RSS was approximately 820 MB; disk size is not memory usage. Punctuation remains fallible, including one awkward comma-only boundary. See `punctuation-tagger/REPORT.md`.
- Actual optional Qwen lazy-load smoke returned its first native result in 1.27 ms while loading; later guarded model output took 105–150 ms. `background-warm.json` records this separate synthetic check.

## Open-source comparison

[OpenWhispr cleanup](https://docs.openwhispr.com/help/dictation/cleanup) uses a separate cleanup stage, including local models. VoiceInk's public GPL app uses prompts for paragraphs/lists, but its current shipping Refine weights have a VoiceInk-only restriction, so they are not reusable here. No GPL implementation or restricted weights were copied. Detailed sources and pinned references: `SOURCE_RESEARCH.md`.

The separately trialed Apache-2.0 [Quobi/Quill](https://huggingface.co/Quobi/Quill) 0.8B was fast but unsafe for this requirement: 26/48 strict lexical-reference matches, injected BANANA output, dropped emphasis/quoted content and incorrect date correction. None of six requested bullet/paragraph trials met the full requested structure. It is rejected, not shipped. `MODEL_TRIAL.md` retains exact configuration, raw synthetic outputs and timing limits. Coda instead combines its own source renderer with the [punctuation-only model](https://huggingface.co/Horizon-Labs/punctuation-restoration-small) and existing guarded correction fallback. No claim of proprietary Wispr parity.

## Assets and verification limits

The optional punctuation package is installed beside the existing production assets, without changing the existing Python runtime or Qwen weights: pinned int8 ONNX/tokenizer/config + original Apache license/model card and unmodified official ONNX Runtime 1.31.0 inference files/notices, about 377 MB logical. `ORT_DISABLE_TELEMETRY=1` is set before importing the official library, plus API disablement. No downloaded publisher helper is executed; no runtime download happens on app launch. `install_punctuation_assets.py` copies only checksummed already-downloaded files and refuses to overwrite an existing target.

No Computer Use, screen context, private audio, general clipboard, API or live hotkey/insertion test was used. The user independently confirmed meeting capture worked after the prior targeted permission reset; this update does not reset permissions. Stable signing, settings/history preservation, actual installed version and footprint are recorded after installation in `installation.json`. Old app bundles and production assets remain recoverable; tracked scratch reclamation is recorded separately and never includes preexisting caches or user files.
