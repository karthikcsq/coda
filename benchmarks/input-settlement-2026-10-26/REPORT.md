# Input audit and paste settlement

Coda's Control–Option listener uses NSEvent local/global monitors. The local monitor returns the original event; neither monitor posts or replays physical key events. A paste uses one process-scoped Cmd–V down/up pair, both posted synchronously before suspension. A failed or unconfirmed AX write does not trigger a second delivery method. No evidence from the source audit identified Coda as the cause of doubled later physical typing. The parent investigation separately identified and removed two active computer-use keyboard hooks attached to Coda.

An independent latency defect was confirmed: the paste path waited for both matching AX text and a clipboard read, despite ultimately reporting visible insertion as unconfirmed. A consumed paste into an editor with stale AX text therefore occupied the dictation lifecycle for the full three-second deadline. Repeated data-provider reads could also reset the receipt timestamp.

The revised path records the first clipboard-consumption time, settles after at least 150 ms since posting and the original 350 ms grace since first consumption, and stops waiting immediately when a newer clipboard copy replaces its payload. A first read can come from a clipboard manager rather than the intended editor, so the existing post-read grace is retained. An unread payload keeps the existing three-second bound. AX readback occurs once for the final status message rather than being polled; it may still take up to its configured 300 ms messaging timeout. Clipboard restoration remains conditional on this transaction's ownership. Visible insertion remains explicitly unconfirmed, with no automatic retry.

Validation: three isolated named-pasteboard tests passed (all-format restoration, newer-copy preservation, stable first receipt), plus one core policy test covering grace periods, unread deadline and ownership loss. The parent requested preserving the original 350 ms receipt grace after this focused run; the policy boundary assertions were updated and await the parent's final full-suite run. Tests use synthetic text only and never access the general clipboard, post keyboard events, record audio or drive UI. The process sandbox cannot create native NSPasteboard fixtures; the focused suite passed with normal native fixture access. Full app integration and live insertion are left to the parent validation scope. No claim is made that synthetic tests reproduce the user's double-typing symptom.

Reproduce: `CLANG_MODULE_CACHE_PATH="$PWD/.build/ModuleCache" SWIFTPM_MODULECACHE_OVERRIDE="$PWD/.build/ModuleCache" scripts/test.sh --disable-sandbox --filter 'pasteConsumptionSettlesWithoutAccessibilityReadback|guardedPaste'` with native named-pasteboard access.
